# 会话订阅常驻不退订

**Status**: accepted（回溯记录，2026-11-12）

每个会话的订阅一经建立就保持到服务端进程重启：不主动退订，也不靠轮询补齐历史。原因是退订再重订阅会与正在产生的帧竞态，快照只能用于界面归位、不能当历史回放，重订阅的代价远高于常驻。插件因此维护固定数量的订阅槽（16 个），槽位耗尽后新会话无法订阅，重启是唯一的释放路径。

**Consequences**

- 订阅前必须先 resume；否则会收到 -32004。
- 订阅失败要区分不可恢复原因（会话不存在、无权）与服务端瞬时错误，前者不能反复重试。
- 槽位耗尽是设计内状态，界面要给出明确提示并引导重启，而不是静默丢帧。
