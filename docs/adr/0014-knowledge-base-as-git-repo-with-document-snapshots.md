# 知识库以 git 仓库承载，文档快照替代源仓锚点恢复

**Status**: accepted（2026-11-24）

## Context

知识库一期收录的是「指针」：条目只记源路径，内容留在原地。源文件没了就只剩有损的提取文本；一期靠「收录时记下源仓库 HEAD」的锚点到源仓库历史里捞回，但在真实使用中并不可靠——文件收录时还没提交、之后被修改、仓库历史被改写、仓库做过换行符转换，都会让锚点指向取不到或不一致的内容。同时库只存在于一台机器上，整理结果（AI 经 MCP 批量移动、改标签）没有历史可以回退，内容也离不开系统盘。

约束：MCP 服务器是独立进程，与 IDE 共用同一份库文件；IDE 侧是 Kotlin，服务器侧保持纯 Java（编译下限与 fork classpath 见 ADR-0010）。

## Decision

1. **收录即落文档快照**：源文件原始字节逐字节存进库内，源文件变化时由对账覆盖。所有读取出口走同一个解析函数——源文件在就读源文件，否则读文档快照，都没有即失效。锚点恢复整套删除。
2. **条目文件只放对每台机器都成立的事实**：新增内容哈希；落盘状态与源文件修改时间、大小移出条目（状态读取时现算，修改时间与大小记在不进仓的本机缓存）。
3. **整个库目录是一个 git 仓库**：同步 = 暂存全部变化 → 有变化才提交 → 变基拉取 → 有未推送的提交才推送，一次同步对应库的一个完整状态。变基冲突自动中止、不选边。全仓关闭换行转换，文档快照按二进制处理、不参与行级合并。检索缓存与本机缓存不进版本历史。
4. **库位置可整体搬迁**：系统盘只留固定入口（Windows 目录联接，macOS / Linux 符号链接），另留一个指针文件用于入口丢失后重建；MCP 服务器与外部脚本继续只用入口路径。
5. **共用实现只有一份**：文档快照、解析、对账、同步，以及元数据（目录、条目、标签、配置）的读写和收录、元数据编辑的落库规则，都在 `knowledge-core` 里以纯 Java 写一份（`KbContent`、`KbSync`、`KbMetaStore`），IDE 与 MCP 服务器共用。两侧各自只留一层薄接口：IDE 侧是 Kotlin 数据类的外观，MCP 侧负责按路径定位目录、参数校验和结果行。检索打分仍两侧各一份（只读，保持同形）。

## Consequences

- 源文件丢失（删除、改名、切分支、换机器）后内容仍可打开、检索、发给 AI；条目从两态变三态：正常 / 仅文档快照 / 失效。
- 换机器只需在设置页填同一个远端地址再点同步：本地库为空而远端已有历史时，同步直接接入远端历史，整个库取回到当前位置（想放别的盘先改库位置），不设单独的克隆入口；本地已有内容而两边历史不相干时拒绝接入。整理有历史可回溯。代价：同步会把收录文档的全文推到远端，远端必须是私有仓库；文档快照占用随每个内容版本增长；多机的前提是两台机器源路径一致。
- 漂移检测从「修改时间 + 大小」改为「内容哈希为准」，首轮对账为存量条目补齐文档快照。条目格式变更不需要迁移（一期尚未发布）。
- 同一处源文件的变化常被两台电脑各自对账到（对账自动跑、同步要手点）：对账只改内容哈希与大小，不写各台机器自己的时间戳，两边写下的条目逐字节相同，后同步的提交变基后成为空提交被丢弃，不产生冲突。
- 同步取回的文档快照变了，对应条目的检索缓存随之作废、由对账按解析规则重建；否则源文件不在本机的条目在检索和读全文里一直是旧正文。
- 库文件由 IDE 与 AI（经 MCP 整理）交替写入，所以写文件的逻辑不能有两份：两份实现只要在排版、字段写法或排序落位上有一点出入，就会变成历史里的整文件重写、两台机器之间的合并冲突，或两边整理出的结果不同。文件的排版只有一种（逐字段一行）。代价：存量里由旧写法留下的文件（紧凑单行）第一次被写到时整文件变化一次。
- 新增对系统 git、用户的 git 身份与凭证的依赖。自动同步、AI 触发同步、冲突自动解决都不做。
- Windows 目录联接在 JDK 17 上不被当作符号链接：判断是不是联接要看 reparse point 属性位，取真实位置要用解析后的真实路径；搬移和删除只对真实路径操作，穿过入口递归删除会删光库的实际内容。

## Considered Options

- **保留锚点，文档快照只作补充**：两套恢复机制并存，锚点的几种失效情形仍要维护；否决。
- **工作区留在系统盘，文档快照只进对象库（跳过工作区文件）**：合并、暂存、重置都容易出错；否决。
- **元数据仓与文档快照仓分开**：失去「同一个提交 = 同一时刻的完整状态」；否决。
- **共用实现用 Kotlin 写**：可行（fork classpath 里带 Kotlin 运行时），但把 MCP 服务器的类加载押在运行时存在、且版本与编译期合拍上；沿用模块里纯 Java 分词器的先例。
