# 数据根重定向的生效边界：轻任务子进程跟随，主会话进程暂留 home

**Status**: accepted（2026-11-13）

桌面客户端支持把数据目录重定向到自定义位置（`setting.json` 的 `dataBaseDir`）。命令行运行时（CLI）解析数据根只认环境变量 `ZCODE_DATA_BASE_DIR`，未注入时回退用户主目录，并不读取该设置。插件自身读配置的路径助手是跟随重定向的，于是出现同一条渠道定义"插件读得到、子进程读不到"的分叉：润色/标题等轻任务起的独立进程拿不到重定向后的个人渠道配置。

同时，插件的会话列表、置顶/归档、模型调用轨迹等能力存在**直接读写 home 数据根**的路径（会话库、任务索引、轨迹文件）。若把主会话进程单点改为跟随重定向，app-server 与直读侧会各读一份库，删除/归档/置顶等操作会静默作用于错误的库。

> **待验证（2026-11-13）**：维护者对此段提出异议——此前自行做过目录迁移测试，未观察到分叉。正在用一次真实数据目录迁移做前后对照（迁移前基线已存）。复核结论出来前，本段按**假设**而非已证事实看待；若实测无分叉，此处结论与 Decision 第一条的边界需一并修订。

**Decision**

- 数据根只下发给与会话库无关的轻任务子进程：润色/标题的 `generateText` 专用 app-server，以及一次性 CLI 调用。
- 主 app-server 与 CLI `--resume` 通道保持 home 数据根（与直读侧同源）。
- 内置渠道目录的定位（runtime 缓存候选）跟随数据根；安装副本与 AppData 兜底候选次序不变（含历史误拼位置兼容）。

**Considered Options**

- 全量跟随：所有子进程与所有直读路径统一到重定向数据根。收益是单一数据真相，但涉及会话库/任务索引/轨迹读取的迁移与迁移期双源读取，风险与工作量远超本次缺陷。
- 只给一次性 CLI 调用注入：实现最小，但 `generateText` 快速通道仍失效（先降级再可用），润色延迟与失败面仍在。

**Consequences**

- 重定向用户的润色/标题恢复可用，且与桌面端看到同一份渠道定义。
- 重定向用户存在"桌面端会话库"与"插件会话库"两个数据根的既成事实；主会话进程与直读路径的一致性优先于"单一数据根"，这是有意保留的边界。
- 全面对齐（会话库、任务索引、轨迹读取全部跟随重定向）需单独立项，覆盖迁移期双源读取与并发写风险。
